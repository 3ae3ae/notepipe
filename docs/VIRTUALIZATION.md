# 长列表虚拟化立项:阅读页 / 课程库 / 任务列表

2026-09 性能审查(见 BENCHMARKS 相邻记录与本轮审查报告)确认:桌面端三个长内容页面
每次 render 都构建全部元素,无虚拟化。本文件是该工作的立项与设计约束。

> 状态:**已在 2.0.0-rc.2 落地**(阅读页文章流、任务列表、课程库网格均已虚拟化,
> 附带小项「scene 扫描估算进度」同步完成);本文保留为架构说明。

## 背景与收益

| 页面 | 位置 | 现状 | 影响 |
|---|---|---|---|
| 阅读页文章流 | `desktop/src/reader_ui.rs` `reader_page` | 所有 block 构建为元素塞进单个 `overflow_y_scroll` v_flex | 长笔记(数千段+数百图)每次 render 构造数千 AnyElement;叠加事件期重绘,滚动与并行任务时可感知卡顿 |
| 课程库网格 | `desktop/src/course_library.rs`(课程卡片+缩略图) | 全量重建 | 100+ 课程时滚动/重渲染成本高 |
| 任务列表 | `desktop/src/task_ui.rs`(任务行) | 全量重建 | 长历史时同上 |

预估收益:render 成本从 O(N 元素) 降到 O(可视区);大库/长笔记滚动流畅。

## 约束(不可违反)

- **零视觉/交互变化**:布局、间距、文案、滚动行为、键盘操作逐项保持;这是结构替换,不是重设计。
- 遵循 `.agents/skills/course2md-design`:滚动条契约、滚动/动效语义见
  `references/states-and-motion.md`;渲染中不做文件/网络 I/O 的既有原则保持。
- 阅读位置保存/恢复(reading position)、页内搜索定位、图片查看器跳转等依赖滚动位置的
  功能必须继续工作。
- `cargo test --manifest-path desktop/Cargo.toml` 全过,clippy 零新增警告。

## 设计决策

GPUI(本仓库 vendored zed fork + gpui-component)提供:
- `uniform_list`:条目等高,最便宜;需要固定行高。
- `list`:条目可变高,按可视区惰性测量;适合文章流。

按页面选型:
1. **阅读页文章流 → `list`(可变高)**。block 高度天然不一(标题/段落/图片/分隔线)。
   实现要点:把 block 序列铺平为稳定索引的条目源;渲染闭包复用现有 block→元素逻辑;
   滚动偏移与阅读位置保存沿用现有 anchor/索引语义(如现有实现按 anchor 定位,需要
   anchor→条目索引的映射,可复用上一轮的预索引思路)。
2. **任务列表 → `uniform_list`**。任务行等高(现有行组件已是固定行高布局;若个别行
   存在展开态差异,则归入 `list`)。
3. **课程库网格 → 按行分组的 `uniform_list`**。网格按当前列宽把卡片分成每行 N 张的
   行切片,虚拟化单位是「行」而非「卡」;窗口宽度变化时重新分组(现有网格本就有
   响应式列数逻辑)。若分组逻辑导致行高不等,退回 `list`。
